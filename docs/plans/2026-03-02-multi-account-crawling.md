# 多账号拟人化采集架构

> 日期: 2026-03-02
> 决策者: Mason
> 背景: 主号采集 57 条详情后触发 XHS 风控（461 "账号异常"），需要更安全的采集方案

## 问题

1. 单号硬冲容易被风控，feed API 阈值 ~50-60 次
2. 主号（素仁轩运营号）被风控会影响业务
3. 固定时间、固定频率、固定关键词容易被识别为机器人

## 方案选择

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. 继续单号 + 降频 | 最简单 | 主号仍有风险，量不够 | ❌ |
| B. 多账号隔离 + 拟人化 | 主号安全，量可扩展 | 需注册小号+养号 | ✅ 采用 |
| C. 第三方数据平台（千瓜/新红）| 合规、稳定 | 成本高，数据维度有限 | 作为降级方案 |

## 最终方案：多账号 + 两层采集 + 拟人化

### 账号体系
- **主号**（素仁轩运营号）→ 绝不碰自动化，只用手机 APP
- **A 号**（内容博主人设）→ Task 1 内容灵感 + Task 4 趋势发现
- **B 号**（选品生意人设）→ Task 2 选品情报 + Task 3 竞品监控
- 每个号有独立浏览器指纹（UA、分辨率、locale、timezone）

### 两层采集
- **Tier 1 搜索 API**：广撒网，每次 2-3 关键词 × 1-2 页 ≈ 40-120 条，风控松
- **Tier 2 Feed API**：仅对互动分 Top 10 调详情，控量在风控阈值内

### 拟人化
- Cron 触发后随机延迟 0-45 分钟
- 关键词每次随机选子集（shuf），不全搜
- 搜索间延迟 30-90 秒，详情间模拟阅读 10-30 秒
- 启动先逛首页暖场（随机滚动 1-3 次）

### 采集时间窗口
- 晚高峰 20:00-22:00 CST（= Mason 07:00-09:00 ET）→ A 号
- 午休 12:00-13:30 CST（= Mason 23:00-00:30 ET）→ B 号
- 任务不绑死星期几，每周每号 2-3 次

### 数据量控制
- 每个号每天 200-300 次请求
- 一天 1 个 session（~30 分钟）

## 关键约束
- Cookie 存 accounts.json（不再用 base_config.py）
- Cookie 过期 Slack 通知指明哪个账号
- 快代理待切 DPS（按 session 绑 IP）替代当前 TPS
- 养号期（3-5 天）手动操作，不上爬虫
