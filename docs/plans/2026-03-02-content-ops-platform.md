# 素仁轩内容运营中台 — 落地执行计划

> 目标：建立从竞品视频采集 → AI拆解 → 内容生产 → Mason审核 → 排期发布 → 效果监测的全自动管道
> Mason 的唯一触点：Google Drive（素材存储）+ Slack（通知、审核指令、报告）
> 预计分4个阶段落地，每阶段约1-2周
>
> 创建日期：2026-03-02
> 状态：已批准，待凭证到位后执行

### 1.2 涉及的角色

| 角色 | 职责 | 实现方式 |
|------|------|---------|
| **Scout (EMP_0008)** | 竞品视频采集、下载、上传 Drive | Playwright + Google Drive API |
| **Analyst (EMP_0008)** | 调用 Gemini 拆解视频、结果入库 | Gemini API + prompt 模板 |
| **PM (EMP_0008)** | 消费拆解数据、制定各渠道内容策略 | Claude Code + voice.md/brief.md |
| **Creator (EMP_0010)** | 按策略产出各渠道的内容初版 | Claude API + Gemini（图片生成） |
| **Scheduler (新)** | 维护排期看板、通知 Mason | Google Sheets API |
| **Monitor (EMP_0008)** | 发布后效果追踪、数据复盘 | 各平台数据采集 + 分析 |
| **Mason** | 审核内容、确认排期、手动发布 | Google Drive + Slack |

### 1.3 关键架构决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 审核反馈通道 | **Slack 消息驱动**，非 Drive 批注轮询 | Drive Docs API comments 端点解析自由文字不可靠；Slack 消息有明确时间戳和线程，Agent 解析更简单；减少一个轮询定时任务 |
| 素材存储 | Google Drive | Mason 日常已用 Drive，零学习成本 |
| 状态管理 | Slack 线程 + 排期表状态列 | 不额外引入项目管理工具 |
| 内容文案格式 | Google Docs | Mason 可直接查看，但审核意见走 Slack 而非 Doc 内批注 |

### 目录设计原则

1. **按内容主题（而不是渠道）作为一级分组。** 同一个主题会在多个渠道分发，按主题组织方便一次审核所有渠道的素材。
2. **状态流转靠移动文件夹。** 初版 → 修改版 → 已确认 → 已发布 → 效果复盘。
3. **Google Docs 作为文案载体。** Mason 可直接查看，审核意见通过 Slack 回复。
4. **图片/视频直接放同级目录。** Drive 就是素材库，不需要额外系统。

## 三、各渠道内容规格定义

### 3.1 渠道 × 内容类型矩阵

| 渠道 | 主力内容形式 | 次要形式 | 内容节奏 | 调性参考(voice.md) |
|------|-----------|---------|---------|-------------------|
| **小红书** | 图文笔记（6-9张图+文案） | 短视频（1-3分钟） | 每周2-3篇 | 真诚测评，比朋友圈正式一点 |
| **朋友圈** | 图文（1-3张图+短文案） | 短视频（15-60秒） | 每周2-3条，穿插生活 | 最随意，碎碎念，像发给朋友 |
| **抖音** | 短视频（30秒-3分钟） | 图文轮播 | 每周1-2条 | 稍年轻化，节奏可以快一点 |
| **微信视频号** | 短视频（1-3分钟） | 直播片段 | 每周1条 | 接近朋友圈调性，但更完整 |

### 3.2 每个渠道的内容产出物清单

**小红书笔记（图文）：**
```
必须产出：
- 文案正文（800-1500字，含标题、正文、标签）
- 封面图（至少2个方案，1242×1660px 竖版）
- 内页配图（5-8张：产品平铺、质地特写、上脸实测、before/after等）
- 标签组合（5-10个）

可选产出：
- 评论区预埋话术（3-5条自问自答）
```

**朋友圈（图文）：**
```
必须产出：
- 短文案（50-150字，口语化）
- 配图（1-3张，手机拍摄风格，不需要精修）

可选产出：
- 九宫格排版方案（当需要展示多产品时）
```

**抖音（短视频）：**
```
必须产出：
- 视频脚本（分镜 + 口播文字 + 时间轴）
- 拍摄指导文档（场景、光线、角度、设备要求）
- 标题 + 标签组合
- 封面图方案

可选产出：
- 背景音乐建议
- 字幕/贴纸风格指导
- 评论区互动预案
```

**微信视频号（短视频）：**
```
必须产出：
- 视频脚本（同抖音，但节奏可以稍慢）
- 拍摄指导文档
- 标题 + 话题标签

可选产出：
- 关联公众号文章建议
```

### 3.3 同一主题的跨渠道适配规则

同一个产品/主题在不同渠道不是简单的"一稿多发"，而是**同一个核心卖点的不同表达**：

| 维度 | 小红书 | 朋友圈 | 抖音 | 视频号 |
|------|--------|--------|------|--------|
| **核心信息** | 完整测评 | 一个使用片段 | 最抓眼球的1个卖点 | 接近小红书但更口语 |
| **信息密度** | 高（详细） | 低（碎片化） | 中（快节奏） | 中（舒适节奏） |
| **视觉** | 精致图文 | 随拍感 | 强节奏剪辑 | 自然日常感 |
| **CTA** | 收藏+评论 | 私信我 | 关注+评论 | 关注+分享 |
| **发布顺序** | 首发 | 小红书发后1-2天 | 同步或晚1天 | 同步或晚1天 |

### 4.2 排期管理规则

1. **每周一由 PM Agent 提出下周内容计划**，包含主题、渠道分配、发布日期
2. **Mason 周一审批排期**（在 Slack 里确认或在 Sheets 里标注）
3. **创作在发布日前 3-5 天完成初版**，留出审核和修改的时间
4. **各渠道发布顺序**：小红书首发 → 朋友圈（+1天）→ 抖音/视频号（+1-2天）
5. **紧急内容（热点跟进）**：可以绕过排期，但必须 Slack 通知 Mason 确认

## 五、审核迭代流程（Slack 驱动）

### 5.1 完整审核流程

```
Creator 产出初版
    │
    ├── 文案 → 创建 Google Doc，存入 [01-内容创作/初版-待反馈/主题名/渠道/]
    ├── 图片 → 生成/挑选，存入同一目录
    ├── 视频脚本 → 创建 Google Doc，存入同一目录
    │
    ▼
Agent 在 Slack 发通知（带线程 thread）
    "📝 新内容待审核
     主题：补水精华测评
     渠道：小红书(图文) + 朋友圈(图文) + 抖音(视频脚本)
     Drive链接：[一键打开目录]
     请在 [目标日期-3天] 前完成审核
     —
     回复本线程给出反馈，例如：
     • '小红书OK'
     • '朋友圈那段太夸张，改温和一点'
     • '全部OK'
     • '方向不对，重来'"
    │
    ▼
Mason 打开 Drive 查看素材，在 Slack 线程回复审核意见
    │
    ▼
Agent 监听 Slack 线程回复（Slack Events API / 定时拉取线程消息）
    ├── 解析 Mason 回复内容，分类处理（见 5.2）
    │
    ├── 需要修改 →
    │   → Creator 根据反馈修改
    │   → 新版本存入 [01-内容创作/修改版-待确认/]
    │   → 同一 Slack 线程回复 "🔄 修改版已更新 [link]，请确认"
    │
    ├── 确认通过 →
    │   → 将文件移入 [01-内容创作/已确认-待排期/]
    │   → 更新排期表状态为 ✅
    │   → 同一 Slack 线程回复 "✅ [主题][渠道] 已确认，排期 [日期]"
    │
    └── 超过 48h 无回复 →
        → Slack @Mason 提醒 "⏰ [主题] 待审核已超 48h，计划发布日 [日期]"
```

### 5.2 Slack 审核消息解析规则

Agent 从 Slack 线程读取 Mason 的回复，按关键词分类：

| Mason 回复内容 | Agent 解析为 | 动作 |
|---------------|------------|------|
| "OK" / "可以" / "没问题" / "全部OK" | 全部确认 | 所有渠道标记已确认 |
| "[渠道名]OK"（如"小红书OK"） | 单渠道确认 | 该渠道标记已确认，其他等待 |
| "[渠道名][修改意见]"（如"朋友圈太夸张改温和点"） | 定向修改 | Creator 按要求改该渠道 |
| "太夸张" / "不够真诚" / "调性不对" | voice.md 违规 | Creator 重写相关段落 |
| "方向不对" / "重来" / "换个思路" | 全面返工 | PM 重新出策略 |
| "图片换一张" / "封面不好看" | 素材替换 | 重新生成/挑选图片 |
| 其他无法解析的回复 | 不确定 | Agent 在线程追问 "收到，请确认具体是哪个渠道需要调整？" |

### 5.3 为什么用 Slack 而不是 Drive 批注

| 维度 | Drive 批注轮询 | Slack 消息驱动 |
|------|--------------|---------------|
| 触发方式 | 定时轮询（每30分钟扫描） | 事件驱动（Slack Events API）或低频拉取线程 |
| Mason 操作 | 打开 Doc → 选中文字 → 添加批注 | 在 Slack 线程回复一句话 |
| 解析可靠性 | 低（自由文字批注位置不确定，嵌套回复复杂） | 高（线程消息有明确时间序和上下文） |
| 状态追踪 | 需要额外逻辑判断"已解决"批注 | 线程天然是有序对话 |
| 已有基础 | 无（需新建 Docs API 批注读取） | 有（Slack Bot 已配置，频道已就绪） |
| Mason 习惯 | 需要学习在 Doc 里精确批注 | 已有 Slack 使用习惯，零学习成本 |

## 六、效果监测与复盘设计

### 6.1 各渠道监测指标

| 渠道 | 核心指标 | 次要指标 | 转化指标 |
|------|---------|---------|---------|

| **视频号** | 完播率、点赞数 | 分享数、关注数 | 公众号引流数 |

### 6.2 复盘节奏

| 时间点 | 复盘类型 | 产出 | 存放位置 |
|--------|---------|------|---------|
| 发布后72h | 快速数据检查 | 各渠道核心指标截图+简评 | [04-效果复盘/单篇/] |
| 发布后14天 | 深度单篇复盘 | 完整数据+对比基准+改进建议 | [04-效果复盘/单篇/] |
| 每月最后一天 | 月度总结 | 全渠道数据汇总+趋势+下月策略 | [04-效果复盘/月度/] |

### 6.3 效果数据如何反哺内容生产

```
效果数据 → EMP_0008 分析
    │
    ├── 哪种 hook 类型互动率最高？ → 更新 voice.md 话术推荐权重
    ├── 哪个渠道表现最好？ → 调整各渠道投入比例
    ├── 哪类产品内容收藏率高？ → 调整选题优先级
    ├── 什么发布时间效果好？ → 优化排期时间
    └── 哪些图片风格点击率高？ → 更新视觉风格指南
```

## 九、Mason 的日常操作手册

当整个系统跑起来后，Mason 的日常只需要做以下事情：

### 周一（15分钟）
1. 打开 Slack，看 PM Agent 提出的本周内容计划
2. 回复 Slack 确认/调整排期

### 周二-周四（每天10分钟）
1. 收到 Slack "新内容待审核" 通知
2. 点 Drive 链接查看素材
3. 在 Slack 线程回复审核意见（"OK" / "小红书那段太夸张改一下" / …）
4. 收到修改版通知后再确认

### 发布日（每天5分钟）
1. 收到 Slack "今日发布计划" 通知
2. 打开 Drive 拿素材
3. 手动发布到各渠道
4. Slack 回复"已发布"

### 周五（10分钟）
1. 查看本周效果报告（Slack 推送）
2. 有重大发现时回复 Slack 给出调整方向

### 月末（30分钟）
1. 查看月度效果报告
2. 审批 voice.md 更新建议
3. 确认下月内容方向

---

> **核心设计原则：**
> 1. **Mason 只碰 Google Drive 和 Slack**，不需要登录任何其他系统
> 2. **审核流程 Slack 驱动**，Drive 只做素材存储，不做状态管理
> 3. **所有中间处理由 Agent 自动完成**，Mason 只做最终决策
> 4. **每个 Phase 独立可验收**，跑通一个再做下一个
> 5. **数据闭环**：效果数据自动反哺内容策略，系统越用越聪明
