# 客户语言采集与应用

> 内化自 shared/mkt/customer-language.md。
> PM 和 Creator 共同维护。PM 定方法和采集节奏，Creator 执行采集和应用到内容。

## 为什么客户语言重要

- 用户刷到口语化表述会停下来，刷到专业术语会划走
- 搜索栏里用户打的是日常口语，不是专业名词
- 评论区的高赞评论就是最好的文案素材

## 采集方法

### 1. 从策略简报 + 采集数据挖掘（自动化优先）

MediaCrawler 采集的数据经 xhs-analyze.sh 分析后，策略简报的 hot_posts 包含爆帖信息。

**采集流程**：
```
策略简报 hot_posts
  → 找到高互动帖的 note_url
  → 手动查看评论区（当前阶段）
  → 提取用户原话，分类整理
  → 写入 context.md 的客户语言对照表
```

**未来自动化方向**：
- xhs-analyze.sh 增加评论高频词提取
- 自动分类到"痛点词/好评词/意图词"
- 自动更新到 context.md 客户语言段落

重点采集：

| 采集来源 | 要采什么 | 怎么用 |
|---------|---------|-------|
| 爆帖评论区 Top 评论 | 用户怎么描述产品 | 直接引用到文案 |
| "求链接/怎么买"类评论 | 购买意图表述 | CTA 文案参考 |
| 吐槽/差评 | 用户的痛点原话 | 痛点共鸣段落 |
| 提问类评论 | 用户真实困惑 | 选题方向（反馈给 PM） |

### 2. 自有客户反馈

| 来源 | 采集方式 |
|------|---------|
| 微信聊天记录 | 客户咨询时用的词 |
| 售后反馈 | 客户描述使用体验的词 |
| 复购理由 | "为什么又买" 的原话 |
| XHS 自己帖子的评论 | 粉丝互动中的原话 |

## 语言对照表模板

采集后整理到 context.md 的客户语言段落，格式：

```markdown
### 用户说的 -> 我们也这么说
| 用户原话 | 替代掉的专业表述 |
|---------|----------------|
| （从评论区采集） | （对应的专业说法） |

### 用户的痛点描述（可直接用于文案开头）
- "（从评论区采集）"

### 用户的好评描述（可直接用于卖点）
- "（从评论区采集）"

### 购买意图信号（出现这些词 = 想买）
- "（从评论区采集）"
```

注意：语言对照表的实际内容由品牌 PM 或 Creator 采集填写，存放在 context.md 中。本文件只定义方法论。

## 应用规则

1. **标题里用客户语言** -- 口语化搜索词优先
2. **痛点段落引用原话** -- 加引号显得真实
3. **卖点用感知描述** -- "用完脸是滑的" 而不是 "含 xxx 成分"
4. **CTA 用用户的词** -- "想要链接的扣 1" 而不是 "点击购买"
5. **每月更新** -- 语言会变，每月从新评论中补充

## 与内容->转化闭环的关系

评论中的购买意图（"怎么买""求链接"）比点赞数更有参考价值。当帖子评论出现大量购买意图信号时：
- 记录该帖的内容 pattern（标题套路、痛点描述方式、CTA 风格）
- 标记为"高转化 pattern"，在下周选题中优先复刻
- 后续官方 API 接通后，用订单数据验证这些 pattern 是否真正带单

## 采集节奏

| 频率 | 谁做 | 做什么 |
|------|------|-------|
| 每周 | PM | 从策略简报中识别值得深挖评论的爆帖，指派 Creator |
| 每周 | Creator | 手动查看指定爆帖评论区，提取客户原话 |
| 每月 | PM | 汇总更新 context.md 客户语言对照表 |
