# 自优化闭环协议（Optimization Loop Protocol）

> 这是跨 agent 协作协议，不属于任何单一 agent。
> 任何内容/产出从"初稿"到"交给 Mason"之间，都走此流程。

## 流程总览

```
外部输入
├── 用户反馈（互动数据、评论、Mason 反馈）
└── 最新方案（竞品分析、平台新规则、斥候情报）
         ↓
    反馈解析（信号提取）
         ↓
    ┌─→ 优化执行 ─→ Gate 1（机器） ─→ FAIL → 返回优化
    │                    ↓ PASS
    │   Gate 2（内容 checklist） ─→ FAIL → 返回优化
    │                    ↓ PASS
    │   收敛判断 ─→ 未收敛且未达上限 → 返回优化
    │                    ↓ 收敛 or 达上限
    └── 结果打包（优化日志）
                         ↓
                  Gate 3 → Mason
```

## 参与角色

| 角色 | 职责 |
|------|------|
| EMP_0008 内容运营总监 | 收集用户反馈 + 解析优化信号 + 执行 Gate 2 + 调度 Creator/Dev |
| EMP_0010 Content Creator | 执行内容优化（文案/标题/钩子/排版） |
| EMP_0009 Content-Tech Dev | 执行技术优化（参数/模板/管线逻辑） |
| EMP_0006 斥候 Scout | 提供最新解决方案（竞品、平台规则变更、新工具） |
| EMP_0012 Product Architect | 定义优化目标 + 收敛条件（按需激活，非常驻） |
| Mason | Gate 3 最终判断 |

## 三个停止条件（任一触发即停止优化）

### 条件 1：收敛停止
连续两轮优化之间，结果变化低于阈值。
- 定量指标：评分变化 < 5%
- 定性指标：Gate 2 checklist 通过项数不再增加

### 条件 2：轮次上限停止
硬性上限 **3 轮**。
- 第 1 轮：大改（结构性调整）
- 第 2 轮：微调（基于 Gate 检查反馈）
- 第 3 轮：确认（验证收敛）

### 条件 3：Gate 全部通过
Gate 1 + Gate 2 全部通过即停止，不需要凑满 3 轮。

## 每轮优化的内部流程

```
1. 确定本轮优化目标（基于上轮 Gate 反馈或新输入信号）
2. 执行优化
   - 参数优化 → Dev 调参数（时长/语速/格式）
   - 内容优化 → Creator 改文案/标题/结构
   - 结构优化 → EMP_0008 决策，可能需要 EMP_0012 参与
3. 跑 Gate 1（每轮必跑，确保基础没被破坏）
4. Gate 1 PASS → 跑 Gate 2
5. 记录本轮变更日志
```

## 优化边界（agent 可以自主做 vs 必须交给 Mason）

### 可以自主优化（"怎么做"）
- Gate 1 参数：时长上限、格式要求、文件大小（基于平台规则变更）
- 平台参数层（Layer 2）：platforms/*.yaml 参数更新
- 口播/文案风格参数：tone、语速、句式结构
- 标题/标签策略：基于互动数据调整
- 发布时间：基于历史数据调整

### 必须交给 Mason（"做什么"和"为什么"）
- 产品定位变更（战略决策）
- 平台优先级变更（资源分配）
- Gate 3 判断标准变更（品牌价值观）
- 新增/删除优化目标维度
- 风险等级降级（从"高"降到"中"需要 Mason 确认）

## 优化目标必须多维

防止单一指标优化导致目标漂移。

**内容产出的优化目标示例**：
```
综合评分 = 完播率权重 × 完播率
         + 互动率权重 × 互动率（赞+藏+评+转）
         + 转化率权重 × 转化相关指标
```

权重由 Mason 设定，agent 不能自行调整权重。

**目标漂移检测**：
- 每轮优化后检查所有维度，不只是本轮优化的目标维度
- 如果某维度连续 2 轮下降（即使其他维度在提升），标记为"目标漂移风险"，报告给 EMP_0008
- EMP_0008 判断是否需要 escalate 给 Mason

## 反馈解析规则

用户反馈不能直接变成优化指令，需要经过解析：

| 原始反馈 | 错误解读 | 正确解读 |
|---------|---------|---------|
| "视频太长" | 把视频缩短 | 检查完播率曲线，找到流失点，缩短到流失点前 |
| "讲得太浅" | 加更多信息 | 检查是否信息密度低（废话多），还是真的缺内容 |
| "看不懂" | 简化内容 | 检查是用词问题、逻辑顺序问题、还是前置知识缺失 |
| 收藏率高但转化低 | 加更强 CTA | 可能是内容和产品关联度低，而非 CTA 问题 |

**关键原则**：反馈是症状，不是诊断。先定位根因，再决定优化方向。

## 结果打包（优化日志）

给 Mason 看的不只是最终结果，还包括优化过程：

```markdown
## 优化日志 — [内容标题]

### 输入信号
- 用户反馈：[具体反馈内容]
- 新方案：[斥候情报或竞品发现]

### 优化过程
| 轮次 | 改了什么 | 为什么改 | Gate 1 | Gate 2 |
|------|---------|---------|--------|--------|
| 1    | ...     | ...     | PASS   | 2 FAIL |
| 2    | ...     | ...     | PASS   | PASS   |

### 收敛判断
[为什么在第 N 轮停止]

### 最终结果
[产出物 + 所有维度的当前状态]

### 遗留问题
[如果有无法自主优化的问题，列出来等 Mason 决策]
```

## 新项目接入

当新项目/新平台加入体系时，QA 需要同步扩展：

1. **EMP_0012** 跑 Checklist A 时，输出"QA 需要新增什么"
2. **EMP_0002** 新建 `shared/qa/platforms/<platform>.yaml`（如果是新平台）
3. **EMP_0008** 评估 `gate2_checklist.md` 是否需要扩展，或新建项目专属 checklist
4. **EMP_0012** 评估 `risk_categories.md` 是否需要新增风险类型（Mason 批准）
5. 优化目标维度和权重由 Mason 设定

触发机制：EMP_0012 的 Checklist A 第 5 题"验收标准是什么？"自然引出 QA 需求。
