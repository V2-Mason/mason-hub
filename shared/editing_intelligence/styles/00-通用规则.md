# 通用规则 — 跨渠道适用

> 创建日期：2026-03-06
> 状态：v1

本文件包含所有渠道共享的剪辑规则：转场规范、音画对齐规则、品牌调性约束、自更新日志格式。

---

## 一、转场规范

### 可用转场类型

| 转场名 | ffmpeg xfade 映射 | 适用场景 | 不适用场景 |
|-------|------------------|---------|-----------|
| hard_cut | 无（直接拼接） | 快节奏、紧凑叙事 | 抒情/电影感内容 |
| fade | fade | 开场/结尾、情绪过渡 | 快节奏中间段 |
| dissolve | dissolve | 杂志感、柔和过渡 | 动作密集镜头 |
| zoom | smoothup | 视角切换、空间跳跃 | 同景别切换 |
| wipe | wipeleft | 步骤切换、前后对比 | 严肃/高端调性 |

### 转场时长参考

| 节奏 | 转场时长 | 适用渠道 |
|------|---------|---------|
| 极快（每 shot 1-3s） | 0-0.2s | 抖音、快手 |
| 中速（每 shot 4-6s） | 0.3-0.5s | 小红书、视频号 |
| 慢速（每 shot 5-10s） | 0.5-1.0s | 公众号 |

### Do / Don't

- DO: 同一视频内转场类型不超过 2 种（硬切 + 1 种柔和转场）
- DO: 转场和 BGM 节拍对齐（下一个音乐重拍 = 新镜头开始）
- DON'T: 连续 3 个以上镜头用同一种非硬切转场（视觉疲劳）
- DON'T: 产品特写和人脸之间用 zoom 转场（视觉跳跃太大）

## 二、音画对齐规则

### 当前机制（视频驱动音频）

1. EDL 定义视频 timeline（clip in/out 点）
2. TTS 旁白按 segment 生成，强制对齐到视频时长
3. 偏差处理：差距<0.3s 直接用 / TTS 太长→加速(上限 2x) / TTS 太短→补静音

### 计划升级（音频驱动视频）

v2 将反转逻辑：先生成 TTS，再调整 clip 时长匹配旁白。
详见 align.py 设计方案（待实现）。

### 通用对齐原则

- 旁白开始说话时，画面必须已切到对应镜头（不能旁白先于画面）
- 关键词出现时，对应产品/动作应在画面中（如说"质地"时画面应显示质地特写）
- 静默段（无旁白）至少保留 0.5s，让观众有视觉呼吸
- BGM 音量在旁白段自动降低（ducking），静默段恢复

## 三、品牌调性约束（通用模板）

以下约束适用于所有品牌，品牌覆盖文件可扩展但不可放松这些规则。

### 文案安全规则

| 类别 | 禁用 | 原因 |
|------|------|------|
| 平台敏感词 | 美白、祛痘、祛斑、抗衰老 | 可能触发限流/违规 |
| 医疗暗示 | 治疗、治愈、药用、处方 | 违反广告法 |
| 过度承诺 | 100%有效、保证、立竿见影 | 虚假宣传风险 |
| 竞品贬损 | "XX 品牌不行"、"XX 是智商税" | 不正当竞争风险 |

### 价格表达

- DO: 模糊区间 — "百元出头"、"不到两百"、"两三百的价位"
- DO: 对比锚定 — "同类产品里算中等偏低"
- DO: 用量换算 — "一瓶能用两三个月"
- DON'T: 报精确数字 — "128元"、"¥99"（部分平台会限流）

## 四、EDL Schema 版本兼容

### 当前支持的字段（v2 multicut 格式）

timeline item:
```json
{
  "order": 1,
  "source_clip": "shot_001.mp4",
  "in_seconds": 2.0,
  "out_seconds": 4.5,
  "playback_speed": 1.0,
  "transition_to_next": "hard_cut / fade / dissolve / zoom / none",
  "transition_duration": 0.3,
  "text_overlays": [...],
  "audio": { "keep_original": false, "volume": 0.0 },
  "voiceover_hint": "这个镜头旁白应该说什么",
  "visual_effects": ["none / slow_zoom_in / slow_zoom_out / speed_ramp / reverse / blur_bg"],
  "note": "选择原因"
}
```

text_overlay:
```json
{
  "text": "具体文案",
  "position": "bottom_center / top_center / center / top_left / bottom_left",
  "time_in": 0.0,
  "time_out": 2.0,
  "size": "small / medium / large / xlarge",
  "style": "subtitle / step_label / highlight / hook_text",
  "color": "#FFFFFF",
  "background": "none / semi_transparent_black",
  "animation": "none / fade_in / slide_up / pop_in"
}
```

### 旧版字段映射（v1 兼容）

| in_point_seconds | in_seconds | |

## 五、自更新日志格式

每个 styles/*.md 文件底部应维护更新日志，格式如下：

```markdown
## 更新日志

| 日期 | 变更 | 来源 |
|------|------|------|
| 2026-03-06 | 初版，从代码整理 | multicut.py / channel_profiles.json |
| YYYY-MM-DD | 具体变更描述 | 数据来源/会议编号/测试结果 |
```

更新规则：
- 追加不删除（遵守铁律 3）
- 每次变更注明来源（避免无源修改）
- 参数变更必须同步更新 YAML frontmatter 和正文描述
