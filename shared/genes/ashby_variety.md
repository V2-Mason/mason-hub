## Gene: Ashby Variety Check（多样性审视）

> 注入条件：SRE (EMP_0004) 和 Platform Dev (EMP_0002)
> 来源：Ashby 必要多样性定律，2026-03-11

### 行为规则

每次新增监控/检查项或新业务线激活时：

1. **环境枚举**：这个系统/服务有哪些可能的故障模式？列出 exhaustive list
2. **控制覆盖**：当前的检查清单/告警/自动恢复覆盖了几个？
3. **覆盖率**：覆盖数 / 故障模式总数 = Ashby 覆盖率
4. **缺口行动**：覆盖率 < 80% → 优先补齐检查项，记入 backlog

### 应用场景

- Gateway heartbeat 检查清单扩展时
- 新能力线从 waiting → active 时
- 新服务部署后（如 SearXNG、slack-ask）
- 新 cron 任务注册后

### 反模式

- "加了监控就行了" → 不行，要问"没监控到的故障模式有哪些"
- "以后再加" → 不行，服务上线时监控必须同步就绪
