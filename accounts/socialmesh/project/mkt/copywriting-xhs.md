# XHS 文案框架

> 内化自 shared/mkt/copywriting.md，针对小红书平台特化。
> Creator (EMP_0010) 写 XHS 帖子时参考本文件。
> 品牌调性和禁忌词从 context.md 获取。

## 核心原则

1. **清晰 > 聪明** -- 用户 1 秒看不懂就划走了
2. **好处 > 功能** -- 感知描述优先于专业术语
3. **客户的话 > 你的话** -- 评论区的表述比专业术语有效 10 倍（参考 customer-language.md）
4. **具体 > 模糊** -- "3 天看到变化" 而不是 "效果显著"
5. **展示 > 声明** -- 对比图/使用过程 > "效果惊人！"

## 文案结构

### 1. 钩子（Hook）-- 前 2 秒

决定用户停不停留。参考 `hooks-xhs.md` 的标题和开头公式。

### 2. 痛点共鸣 -- 说出用户的处境

```
模板: 是不是也遇到过 {具体场景}？{情绪描述}。
```

要点：
- 描述**场景**而非问题（用感知语言，不用专业术语）
- 用**情绪词**（焦虑/崩溃/无语/沉默了）
- 最好用**客户原话**（从 customer-language.md 的对照表中选取，或从评论区挖）

### 3. 解决方案 -- 产品/建议

```
模板: {发现经过}，试了 {产品}，{具体变化}。
```

要点：
- 引入要**自然**（"被安利"/"无意间发现"/"用了 N 年的老粉"）
- 变化要**具体可感知**（"脸是滑的" > "皮肤变好了"）
- 避免**广告感**（不说"强烈推荐"/"必买"）

### 4. 信任构建 -- 为什么可信

| 信任元素 | 怎么用 |
|---------|-------|
| 使用时长 | "回购第 3 瓶了" |
| 具体数字 | "坚持用了 28 天" |
| 身份背书 | 参照 context.md 中的品牌人设 |
| 社交证明 | 销量数据、他人评价 |
| 对比展示 | 使用前后对比图/视频 |
| 真诚让步 | "唯一缺点是 xxx"（增加可信度） |

### 5. 行动引导（CTA）

| 场景 | 好的 CTA | 差的 CTA |
|------|---------|---------|
| 种草帖 | "链接放评论区了" | "快去买！" |
| 教程帖 | "先收藏，{场景}用得上" | "记得关注" |
| 互动帖 | "你们{问题}？评论区聊" | "点赞收藏" |
| 品牌号 | "想试的扣 1，私聊发{东西}" | "购买链接在主页" |

## XHS 平台规范

- 标题 <= 20 字
- 正文建议 300-800 字（太短没信息量，太长看不完）
- 前 3 行必须抓人（展开前只看这些）
- 标签 5-10 个（含品类词 + 场景词 + 热度词）
- 不放外链，引导评论区/私信

## 质量检查清单

Creator 写完后逐条过：

- [ ] 标题能让人停下来吗？（挡住正文只看标题，会不会点？）
- [ ] 标题在 20 字以内吗？
- [ ] 前 3 行抓人吗？（XHS 展开前只看 3 行）
- [ ] 有没有说人话？（读出来像聊天还是像广告？）
- [ ] 好处具体吗？（能感知的变化 vs 抽象形容词）
- [ ] 有信任支撑吗？（不是空口说好）
- [ ] CTA 自然吗？（不像在推销）
- [ ] 有没有品牌禁忌词？（查 context.md 禁忌清单）
- [ ] 有没有 XHS 平台禁忌？（跨平台引流词、医疗功效宣称）
- [ ] 正文 300-800 字？
- [ ] 标签 5-10 个？

## 与自动化管道的对接

3. Mason 从 READY 队列取内容，手动复制到 XHS APP 发布
4. 发布后数据回流到下一轮采集分析，形成闭环
