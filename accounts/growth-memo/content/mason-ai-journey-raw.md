# Mason 的 AI 经历原始素材

> 用途：#001 脚本的核心原料
> 创建日期：2026-03-27
> 来源：Mason 口述（brainstorming session）

## 时间线

### 2023年：好奇期
- GPT 刚火的时候开始用
- 一直当聊天工具/作业辅助神器
- 对 AI 没有特别关注
  - 出错率高
  - 能力有限
- 没有深入了解

### 2024-2025：接触 Agent 概念
- 通过 Liam Ottley 的视频第一次了解 AI Agent 概念
- 大概了解了 AI 发展现状，但只留了个印象
- 转折点：Meta 收购 Manus
  - 看到新闻后自己尝试了一次 Manus
  - **第一次感受到 AI 真的可以帮忙做事情了**
  - "好像新的时代真的来了"

### Manus 时期（1-2个月）：上瘾期

**3D打印网站项目的起源：**
- 朋友想玩3D打印，但苦于不会设计
- 一直要请教别人代做，效果也不一定好
- Mason 想法："为什么我不自己做一个网站来让每个人自己定制3D玩偶、手办、挂件"

**开发过程：**
- 最一开始做得很粗糙（Mason有效果对比图）
- 迭代过程让人上瘾
- 作为完全没有技术背景的人，每次 debug、迭代、哪怕完善一个小小的设计改动，都有很强的满足感
- 这种满足感不断 push 自己用更多 credit 继续做
- 每天回到家第一件事就是继续更新项目
- **有连续几个通宵**

**痛点：**
- Manus 很容易出错
- 花十个小时设计，80% 时间在 debug
- 原因（Mason自己分析）：
  - 非技术出身
  - 一开始想到什么做什么，开发路径没有规划
  - 为了把某个功能做完美，或在网上看到更优秀的方案，就 push 自己做到完美
- 结果：每天有新东西、有进步，但技术债越来越多

**Manus 时期收获：**
- 大概知道了 Vibe Coding 的感觉
- 但不了解各模型之间的差异，只觉得"能用就行"

### 两个关键问题的产生
1. Manus 的 debug 太难受，有没有更好/更强的工具？
2. 希望能有一个 Agent 可以自动开发，这样只用规划想做什么，未来有新项目就可以用这套 Agent 开发所有项目，实现可复利效果

### 2026年2月：转向 Claude

**选择过程：**
- 目标投向御三家：OpenAI、Google、Claude
- 以及当时很火的 ClawdBot（后改名 MoltBot，又改名 OpenClaw）
- 用过 ChatGPT 和 Gemini，唯独没用过 Claude
- 加上 ClawdBot 是由 Claude 诞生的
- 决定使用 Claude

**Claude 带来的变化：**
- **打开了对 AI 时代的大门**
- 工程能力更强
- debug 次数比之前少了很多

**能力成长轨迹：**
1. 从要求自己 debug 次数变少
2. → 开始思考架构的设计
3. → 开始比较模型的强弱
4. 每天废寝忘食地学习

**驱动力的两面：**
- 一方面：上瘾
- 另一方面：害怕被拉下
  - "今天如果没学懂，很快就会被时代淘汰"

### 焦虑循环
```
每天新闻资讯 → 焦虑
→ 焦虑 push 学习
→ 学习后开始实践
→ 忘记时间，忽略身体
→ 每多出一个 GitHub 新项目，毫不犹豫直接应用到自己项目里
→ 害怕自己掉队
```

**和 Manus 时期同样的循环：**
- 忽略整体项目迁移
- 一直往一个方向更新
- 模型也好、架构也好，永远选最新最热的
- 忽略了对整个项目的影响

**焦虑具体表现：**
- 觉得自己对 AI、设计流程、配置探索的进步很慢
- 同时期看到各种资讯，觉得无比焦虑
- 睡眠不好

### 转折点：觉醒

**行动：** 休息了两天，和女朋友出去散心

**开始思考的问题：**
1. 我到底想做什么？
2. 我真的需要参考这么多信息吗？
3. 这个时代信息太多，AI 让原本爆炸的信息时代更加爆炸，而且真假更难辨
4. 我该怎样主动筛选出对自己有效的信息？哪方面信息是不需要的？

**形成的方法论：**
- 每次开发前定好目标和验收标准
- 无论中间出现什么，不修改当前目标
- 新技术可以作为做完之后的参考，但不应该直接影响整个项目进程
