## Act 1 — 起因: 为什么不买 SaaS (60-75 秒)

> 2026 年 2 月 26 号, 我做了一个决定: 不再为任何一个生产力 SaaS 续费, 自己写.
>
> 起因很俗——那个月, 我同时在付 Notion + Todoist + Obsidian Sync + Superhuman + Raycast Pro + Grammarly + Linear + Zapier……粗略一看, 每个月固定支出接近 [[$X]] 美元. 关键是, **我每个工具都只用了 20%**. 剩下 80% 要么不会用, 要么和别的工具重复.
>
> 然后我想明白一件事: 我不是需要一个 "更好的 SaaS", **我是需要一个属于我一个人的操作系统**. 我的工作方式别人不懂, 设计再好的通用软件都是 20% 命中率.
>
> 于是我开 Claude Code, 敲第一个 commit: `initial: mason-hub full backup`. 时间是晚上 8 点 04 分.

**时长**: ~75 秒

**自审**:
- C3 数字: 2 月 26 号 (真) + "80% 不用" (类比 Pareto, 算锚点) + "晚上 8 点 04 分" (真实 git 时间戳) ✓

## Act 2 — 过程: 16 个 Agent 是怎么涨出来的 (90-105 秒)

> 第一个 commit 是 2 月 26 号. 到今天 4 月 8 号, **42 天整**.
>
> 这 42 天里, 我真正开发的天数是 31 天. 也就是说, 有 11 天是完全没写代码的——出差, 睡懒觉, 陪家人, 或者在思考下一步到底要写什么.
>
> 第 1 天我只有 1 个 Agent——Gateway, 负责跟我对话, 路由任务. 第 7 天我加了 Dev Agent (EMP_0005) 负责写代码, 加了 Data Engineer (EMP_0014) 负责管数据. 当时我以为 3 个 Agent 就够了.
>
> 结果第 10 天, Dev Agent 开始迷路——它不知道代码该写在哪, 也不知道哪些文件不能碰. 我意识到: **我缺的不是更多的 Agent, 是让每个 Agent 知道自己边界的架构**.
>
> 于是我写了第一个版本的 `CLAUDE.md`, 里面列: "你是谁, 你能碰什么, 什么时候要请示". 这个文件后来演化成了 mason-hub 的核心——每个 EMP Agent 都有自己的 config.md 和 memory/ 文件夹.
>
> 今天, mason-hub 里有 16 个 EMP Agent, 从 EMP_0000 到 EMP_0015, 每个都有明确的岗位描述 + 历史记忆 + 汇报路线.

**时长**: ~105 秒

**自审**:
- C3 数字: 42 天 / 31 天 / 1 Agent / 3 Agent / 7 天 / 10 天 / 16 Agent → 7 个真实数字锚点 ✓

## Act 4 — 7 件事 (50-75 秒, 精简版)

> 我学到的 7 件事, 快速过一遍:
>
> 1. **Claude Code 不是助手, 是合伙人**——你给它架构, 它给你代码. 没架构 = 没代码.
>
> 2. **CLAUDE.md 是契约, 不是文档**——写给自己看的规则, AI 比你自己更守.
>
> 3. **每个 Agent 必须有边界**. Agent 失控不是 AI 的错, 是你没写清 "你不能碰什么".
>
> 4. **Session 沉淀比代码重要**. 我有 29 个 session 收工记录, 每个都是一个"为什么当时这么做".
>
> 5. **skill 装 73 个, 真用的只有 20 个**. 别被数量骗, 按使用频次排序才见真相.
>
> 6. **Learning 要写在 vault 里, 不写在代码注释里**. 代码会变, 教训不会. 我现在有 44 篇 learnings.
>
> 7. **35 岁不是晚, 35 岁是"你终于知道自己要什么"**. 20 岁的我肯定写不出这个架构——因为 20 岁的我根本不知道自己要什么.

**时长**: ~75 秒

**自审**:
- C3 数字: 29 session / 73 skill / 20 真用 / 44 learnings / 35 岁 = 5 个硬数字 ✓
- C4: "7 件事" 清单感 = 强实操标志 ✓
- C5 可抄作业: 第 5 点"按使用频次排序"暗示评论区领 skill 清单 ✓
- C6: "我学到" "我有" "我现在" "20 岁的我" ✓
- C7: 全部命中独立开发 + 35+ 转型 + 工具栈 ✓
