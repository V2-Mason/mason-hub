# 评论挖掘方法论 — 5 路径 + 7 位置完整设计

**核心命题**: 如何从 B 站公开数据里系统性挖出"真痛点"? 每次挖需都是从零开始是不可持续的, 必须建立可循环的工作流。

**和 _dictionary/ 的关系**: 本文档是**方法论层**, _dictionary/ 是**数据层**。方法论告诉你"怎么挖", 词典告诉你"挖到了什么"。

---

## 第一部分: "真痛点"的定义和陷阱

### 评论区 4 种信号

| 类型 | 例子 | 价值 | 陷阱 |
|---|---|---|---|
| **吐槽** | "Cursor 贵死了" | 情绪发泄 | 不等于愿意付费解决 |
| **祈使句** | "求资料 / 需要系统教程" | 中 | 可能只是点赞式互动 |
| **真实案例** | "我用 Cursor 写了小程序, 解决小卖部记价格" | **最高** | 容易被淹没在娱乐评论里 |
| **深度抱怨** | "找了半小时才发现 sql 里 endTime 和 eTime 不一样" | **高** | 样本少, 需要精读 |

**真痛点 ≈ 真实案例 + 深度抱怨 + 高赞祈使句的交集**

单独一类都会骗你。

## 第二部分: 5 条挖需路径

### 路径 1: 按金主品牌反推 (⚠️ 对 Mason 场景不重要)

**逻辑**: 金主投了谁 = 该品牌认为谁的受众能转化

**用途**: 只作为"商业化 sanity check", 不是主挖掘路径

**注意**: 根据 Growth_Memo_Revenue_Model.docx 方案 D, Mason 走粉丝经济, **不需要详细的金主品牌清单**. 这条路径降级为"半年一次的市场确认"

**具体做法 (如果要跑)**:
- 从 B 站搜"恰饭 AI" / "商单 AI" / "赞助 编程" 等找真实商单视频
- 不是从 AI 工具品牌名反向搜

### 路径 2: 关键词轮次 (主挖掘路径)

**逻辑**: 用户的主动搜索词代表真实查询意图

**用途**: 维护"需求词典", 每 1-2 个月跑一次

**关键原则 (从 round1 → round2 的教训)**:
- **关键词必须从上一轮 backlog 来, 不是临时猜**
- 参考: `_dictionary/keywords.json` 的 decision 字段 (keep/deprecate/conditional)
- 过滤 deprecated 词 (如"独立开发者/个人项目/一人公司/AI 创业/indie hacker")

**round2 候选词选择规则** (有证据支持):
- 从 AUDIENCE_PERSONAS v1.0 的 8 需求板块里, 每个板块提取 2-3 个"未被挖透"的词
- 每个候选词**必须有 round1 证据背书**, 不是我凭直觉写的

### 路径 3: 竞品画像挖掘 (质量最高)

**逻辑**: 竞品的评论区 = 你的潜在受众的真实声音

**用途**: 每季度大挖一次, 更新 AUDIENCE_PERSONAS

**目标账号** (round2 应该挖的):
- 4 Tier 1: 鱼皮 / ezindie / 小Lin说 / 巫师
- **Genji 新号** (491266931, 77 视频, 最接近 Mason 定位)
- **狗勾** (可选, 93 视频, 恰饭方法论专家)

**采集参数**: 每视频 25-50 条热评 (Genji 给 50, 其他 25)

### 路径 4: 行动导向短句 (高信号密度)

**逻辑**: 真正有付费意愿的不是"求资料"的, 是"我试了但卡住了"的

**用途**: 写新视频前反向验证痛点真实性

**示例短句** (基于 round1 的反向提炼):
- "Cursor 太贵" / "Claude 限额" / "token 花完"
- "AI 代码跑不通" / "AI 写的不能用" / "AI 编程 踩坑"
- "一人公司" / "副业 AI"

### 路径 5: 跨平台三角验证

**逻辑**: 单平台的"高赞评论"可能是回声室, 真痛点应在 B 站 + 小红书 + 知乎同时出现

**用途**: 重大决策前的终极验证, 关键决策时做一次

**时机**: 对"可抄作业是市场空白"这种核心品牌主张的验证 — 但已经在今天的三层数据里做过了, 短期不需要再做

### 5 条路径的组合使用

| 频次 | 路径 | 目的 |
|---|---|---|
| 每次写新视频前 | 路径 4 (行动短句) | 反向验证痛点真实性 |
| 每 1-2 月 | 路径 2 (关键词轮次) | 维护需求词典 |
| 每季度 | 路径 3 (竞品画像) | 更新 AUDIENCE_PERSONAS |
| 半年一次 | 路径 1 (品牌反推) | 商业化 sanity check |
| 重大决策前 | 路径 5 (跨平台三角) | 过滤回声室 |

## 第三部分: 7 个品牌位置的完整评估

**测试时间**: 2026-04-08 (蓝条 API 测试)

| 位置 | 可信度 | 爬取难度 | 实际结论 |
|---|---|---|---|
| **1. 视频简介 desc** | ⭐⭐⭐⭐⭐ | 低 | ⚠️ **部分可用** — view API 匿名, 但某些视频返回空 (Genji/狗勾 全空, 鱼皮有数据) |
| **2. B 站"蓝条"广告声明** | ⭐⭐⭐⭐⭐ | — | ❌ **匿名不可用** — HTML `__INITIAL_STATE__` 里没有 videoData.desc, `adData` 字段是页面右侧 banner 不是视频内置 |
| **3. 视频标题** | ⭐⭐⭐⭐ | 0 | ✅ **已在手** (video_list.tsv), 0 请求 |
| **4. 视频开场 5-15 秒 (口播)** | ⭐⭐⭐⭐ | 0 | ✅ **已在 full_text 里**, 0 请求 |
| **5. 置顶评论** | ⭐⭐⭐ | 1 请求/视频 | 评论爬时顺便拿 |
| **6. 视频内 BGM/OCR** | ⭐⭐ | 极高 | ❌ 放弃 (需要下载视频+OCR) |
| **7. 弹幕** | ⭐ | 1 请求/视频 | ❌ 暂不做 (噪声比极低) |

### 蓝条 API 测试结论

**测试过的方法**:
1. `view` API 匿名 — 部分返回 desc (2/4 样本)
2. `view/detail` API — 412 拦截, 需要 WBI 签名
3. HTML `__INITIAL_STATE__.videoData.desc` — 全部返回空
4. HTML 里的 `isAd`/`cc_mark`/`商业推广` 文本搜索 — 0 命中
5. `adData` 字段 — 拿到了但这是页面右侧 banner 不是视频内置

**最终结论**: **蓝条 API 匿名不可用**. 替代方案是位置 1 + 3 + 4 + 5 四合一。

### 最佳爬取策略 (按 ROI 排序)

**策略 A: 位置 3 + 4 (0 请求, 立刻可做)**
- 扫 video_list.tsv 标题 + full_text.txt 前 30 行

**策略 B: 位置 1 (+300 请求补 desc)**

- 每视频调一次 view API

**策略 C: 位置 5 (评论爬时顺便)**

**策略 D: 评论全量搜"广告/恰饭/赞助"**
- 观众视角的金主识别

## 第六部分: 匿名爬取风险评估

### 真实风险

**风险 1: IP 频率限制**
- 评论 API: 每秒 1-2 次安全, > 5/秒 开始丢数据
- 连续 100-200 视频 → IP 降速
- 触发后等 5-15 min 自己恢复
- **Mitigation**: sleep 1.5-2.5s 随机 + 每 50 视频停 3 分钟

**风险 2: 评论 API 的隐藏限制**
- 热度排序 (mode=3) 最多只返回前 ~200 条热评
- 再往后翻返回空或 stale 数据
- **这不是 bug 是 B 站设计**, 你拿到的是金子 (200 条高热度 + 回复, 覆盖 95% 共识)

**风险 3: 空间 API (space API) 412 拦截**
- `/x/space/wbi/arc/search` 需要 WBI 签名或 cookies
- **替代方案**: yt-dlp `--flat-playlist` 能绕过 (已验证, Genji probe 成功拿到 77 BV)

### 3 层授权的完整对比

| 授权级别 | 能做什么 | 风险 | 适用场景 |
|---|---|---|---|
| **匿名 (无 cookies)** ✅ | 搜索 / 抓评论 / view API / 看统计 | 零 | 日常挖需 |
| **游客 cookies** | 同上 + 减少反爬触发 | 低 | 高频大批量 |
| **登录 cookies** | 同上 + 部分隐藏内容 + 行为关联 | **中** (账号可能被标记) | 不推荐 |

**明确结论: 不需要用 Mason 自己的账号爬评论, 匿名模式就能用**
