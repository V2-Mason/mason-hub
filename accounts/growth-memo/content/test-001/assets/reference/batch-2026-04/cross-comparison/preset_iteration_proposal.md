## 3. Preset 阈值规则修正

### 当前规则的问题

`bilibili-creator.md` 和 `bilibili-dev-content.md` 都用同样的 "Δ ≥ threshold AND MidV < 30%" 双条件。但巫师 C5 Δ=+0.917 + MidV=61% 暴露了一个边界 case: 当 N 大 (57) 且 Mid 段宽 (33), Mid 违反率自然偏高, 这不能否定 Δ 本身的强度。

### 修正提案: 三级判定 (替代当前的两级 strong/weak)

```
强分界规律 (Sharp boundary):
  Δ ≥ thr AND MidV < 30%
  描述: "Top vs Bot 锐利分界, 中腰也吃这套"
  使用场景: 可作为爆款公式的核心因子 (例: 伦巴 C5 +0.83)

强信号-弱普适规律 (Strong signal, weak generalization):
  Δ ≥ thr AND MidV 30-60%
  描述: "Top vs Bot 强分化, 但中腰大量样本不遵循 → 必要条件但非充分条件"
  使用场景: 可作为爆款的"门票" 但不能单独保证爆 (例: 巫师 C5 +0.917 / MidV 61%)

弱规律 (Weak signal):
  Δ in [0.20, thr)
  描述: "有方向但不显著"
  使用场景: 辅助因子, 不可单独引用

无差异:
  |Δ| < 0.20
  描述: 不能用作规律
```

### 影响分析

- **伦巴 C5** Δ=+0.83, MidV<30% → 仍然是 "强分界规律"
- **巫师 C5** Δ=+0.917, MidV=61% → 从"弱规律" 升级为 "强信号-弱普适规律"
- **巫师 C6** Δ=+0.583, MidV=30% → 从"边界 strong"升级为 "强分界规律"
- **ezindie C1/C6/C8** 三个高 Δ 但本质同一机制 → 需要在 Phase 5 加 "**伪相关性自检**" 步骤 (见下面)

## 4. 新增 Phase 步骤: "伪相关性自检"

ezindie 的 C1/C6/C8 和巫师的 C2/C5/C6 都暴露了同一个问题: **多个 check 在 Top 12 上一起 PASS, 看似 3 条独立强规律, 实际是同一机制的不同表达**。

### 提案: 在 Phase 5 后加 Phase 5.5 "伪相关性自检"

**步骤**:

1. 对所有"强规律候选" (Δ ≥ thr) 列出 Top 12 PASS 的 BV 集合
2. 计算两两交集: 如果两个 check 的 Top PASS 集合重叠 >75%, 它们高度相关
3. 把高度相关的 check 合并标记为"同一机制的子规律"
4. 在 patterns.md 输出: "X 条强规律候选, 其中 Y 条相关性 >75% 应合并视为 1 条机制"

**效果**:
- ezindie 的"3 强规律" → 应该标"1 机制 (单主角独白) 体现为 3 个共线 check"
- 巫师的"C2/C5/C6 三连 PASS 在 Top 12 75%" → 应该标"1 机制 (全民话题三件套) 体现为 3 个共线 check"

### Skill 文件修改建议

更新 `~/.claude/skills/creator-hit-factor-grid/SKILL.md`:

1. 在 Phase 5 后加 "Phase 5.5 伪相关性自检" 段落
2. 在 Phase 5 输出格式里加 "**机制聚合**" 字段
3. 在 "Anti-rationalization" 表加一行: "**多个强规律一起 PASS**: 自检相关性 >75% 应合并, 不要号称 3 条独立规律"

## 5. Tier 2/3 hook 分析的轻量 preset

P3 阶段每个账号只采 Top 10 视频, 工作量是 Tier 1 的 1/6。**不需要跑完整 9 check**, 只需要核心 5 个:

| Check | 名称 | 理由 |
|---|---|---|
| C1 | 反差/极端开场 | 通用强信号 |
| C2 | 具名主角 | 是否有 IP 锚点 |
| C5 | 题材已出圈 | 是否追全民话题 (帮助赛道分类) |
| C6 | 数字密度 | 通用强信号 |
| C9 | 可抄作业 | 验证"4/4 共性"假设 (其他账号是否真的不做 C9) |

**目标**: 通过 5 check × 10 视频 × 9 账号 = 450 格快速判断 9 个 Tier 2/3 账号属于哪个赛道类型。如果某个账号 C9 命中率 ≥ 30%, 就是 Mason 的"竞争对手"; 如果 4/4 + 9/9 都接近 0, Mason 的差异化定位被强力验证。

**轻量 preset 文件**: `bilibili-quick-hook.md` (留给下次 session 创建)

## 7. 不立即做的理由

Mason 的 P0 是 Growth Memo 第一期发布, 不是 preset 体系迭代。preset 的修改属于 "工具改进", 不是 "产出"。在没有 Mason 自己的 Growth Memo 数据反馈之前, preset 的进一步迭代没有数据支撑。

**正确的顺序**:
1. Mason 用 `bilibili-mason-target.md` (新建) 写第一期 Growth Memo
2. 发布并跟踪 D7/D30 数据
3. 如果第一期效果好, 验证差异化爆款公式, 把这个 preset 固化
4. 如果效果不好, 用 grid 反向分析自己的视频, 修正 preset
5. **然后才是** preset 体系拆分
