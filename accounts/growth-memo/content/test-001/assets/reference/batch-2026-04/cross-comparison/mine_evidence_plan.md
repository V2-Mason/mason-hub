## 限速和错误处理策略

### 基本规则
- 每请求 sleep 1.5-2.5s (随机)
- 遇到 HTTP 412 或 code=-412 → 立即停止该路径, 等待 10 分钟后 resume
- 遇到 HTTP 403 → 指数退避 (20s → 40s → 80s)
- 每 50 个视频写一次 `_progress.json`, 方便 resume

### 输出结构
```
evidence-2026-04-08/
├── path1_brand/
│   ├── _keywords.json
│   ├── search_results.json
│   ├── comments/BV*.json  (每 BV 一个)
│   └── _progress.json
├── path2_keywords/
```

### 断点续跑
- 每条路径独立 progress
- 挂了之后重跑 `python mine_evidence.py --resume` 会自动跳过已完成的
- 每条评论独立 json 文件, 不会因为中断丢数据
