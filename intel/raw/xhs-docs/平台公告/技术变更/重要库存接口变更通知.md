致亲爱的小红书开放平台合作伙伴：为提供更准确的库存查询能力，更完善的库存同步能力，小红书开放平台对已开发的多个库存接口进行全面升级，平台将于2024年11月20日起启动灰度，请务必于2024年11月20日前尽快完成接口兼容工作；

注意事项：逾期未做兼容的开发者应用，可能出现库存同步相关问题，请大家积极配合，并做好商家和客户的沟通；

  


**【接口变更】**

接口名| 接口说明| 变更说明

inventory.getSkuStockV2| 获取商品库存V2| 新增字段：具体请看接口文档 字段计算逻辑变更：总库存字段含义变更  
接口| 接口说明| 变更说明

**【新老逻辑差异】**

**inventory.syncSkuStock**

灰度前商家传入的库存值仅会影响到普通品的可售库存，而不会涉及到其他渠道的独立库存和订单占用库存。灰度后商家传入的库存值会与该普通品的总库存值进行计算，用得到的差值来去影响到可售库存值。

举例：某个sku当前在平台总共有100件库存，存在80件可售库存，20件占用库存（占用库存=渠道品独立库存+活动独立库存+待支付订单占用库存，即除了可售库存（共享库存）外的其他所有库存值之和）。

商家想将库存值同步为30，老链路会将可售库存修改为30，20件占用库存不变，因此平台上的总库存实际为50。新链路会将可售库存修改为10，20件占用库存不变，因此平台上的总库存实际为30。

如果商家还想将库存值同步为10，老链路会将可售库存修改为10，20件占用库存不变，平台上的总库存实际为30。新链路会保持20件占用库存不变，然后将可售库存一直扣减到0为止，此时平台上的总库存实际为20。这种情况会在返回结果信息里提示商家：同步成功，但有占用库存未扣减，请检查独立库存占用情况和用户待支付订单占用库存情况

目前存在许多商家需要将库存值同步为0的情况，这在新老链路中都会将可售库存设置为0，占用库存不变，在使用体验上完全等价。 总结：新老链路的同步逻辑中，对于占用库存都是无法去修改的，该类型库存需要商家到平台侧手动进行修改，OpenAPI暂不提供该能力。

  


对于多仓区域库存，该接口未做适配逻辑，导致灰度前同步的库存值是默认仓的库存并无实际意义，建议用户使用inventory.syncSkuStockV2接口。灰度后该接口会针对多仓品进行拦截抛错

**inventory.incSkuStock**

对于多仓品，该接口未做适配逻辑，导致灰度前修改的库存值是默认仓的库存并无实际意义，灰度后该接口会针对多仓品进行拦截抛错

**inventory.syncSkuStockV2**

和inventory.syncSkuStock接口同理，区别在于该接口能兼容多仓区域库存商品，适用范围更广

  


**【库存查询接口字段含义说明】**

总库存字段含义变更：

接口历史逻辑中，总库存（total）字段的计算逻辑为：普通品可售库存；在存在渠道品独立库存 & 待支付订单占用库存情况下，总库存值偏小；

接口新逻辑中，总库存（total）字段的计算逻辑为：普通品可售库存（共享库存）+ 渠道品独立库存 + 活动独立库存 + 待支付订单占用库存，即平台侧货品总库存；

废弃以下字段：

standalone，reserved字段已废弃，默认返回0，无实际意义

新增以下字段：

occupiedQuantity：订单占用库存（该商品可售库存被用户下单，处于未支付状态下导致的库存占用）

productChannelQuantity：商品渠道可售库存（该商品衍生的渠道品，分配给其独立库存中的可售部分）

productChannelOccupiedQuantity：商品渠道占用库存（该商品衍生的渠道品，分配给其独立库存中的订单占用部分）

activityChannelQuantity：活动渠道可售库存（该商品分配给活动渠道的独立库存中的可售部分）

activityChannelOccupiedQuantity：活动渠道占用库存（该商品分配给活动渠道的独立库存中的订单占用部分）

以上新增的5个字段为平台侧占用库存，OpenAPI只提供查询不提供修改能力

字段间的关系：

total（平台侧总库存）= available + occupiedQuantity + productChannelQuantity + productChannelOccupiedQuantity + activityChannelQuantity + activityChannelOccupiedQuantity

占用库存 = total - available = occupiedQuantity + productChannelQuantity + productChannelOccupiedQuantity + activityChannelQuantity + activityChannelOccupiedQuantity

**【新老逻辑差异】**

**inventory.getSkuStock**

对于普通品，灰度前只查询了可售库存，未查询渠道独立，活动独立，待支付订单占用库存，导致总库存值偏少。灰度后查询到的是全量库存数据；

对于渠道品，灰度前返回的可售库存值实际为其原品可售库存，与接口含义不符。灰度后查询到的是该渠道品品可售库存；

对于多仓区域库存，灰度前该接口未做适配逻辑，查询到的库存值是默认仓的库存值，并无实际意义。灰度后查询到的是该多仓品的全量库存数据；

**inventory.getSkuStockV2**

灰度前查询到的库存数据仅包括可售库存，未查询渠道独立，活动独立，待支付订单占用库存，导致查询到的总库存值偏小。灰度后查询到的是全量库存数据；

  


**【灰度策略】**

针对每个接口，我们会以商家维度进行灰度。当商家发现响应体中的apiVersion字段值为"V0"时说明还未处于灰度中，当为"V1"时说明处于灰度中，可以据此来调整自己的使用策略；

如果商家已经做好了适配新接口的准备，可以主动要求将自己加入灰度（进官方企业微信群咨询联系平台技术）

如果商家发现新接口影响到了自己业务的正常使用，可以主动要求将自己摘出灰度（进官方企业微信群咨询需联系平台技术）
