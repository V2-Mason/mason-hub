# 虚拟充值开平公告

## 1、业务场景

针对充值类虚拟商品，为了提高用户交易履约体验和商家经营效率，平台将不再支持原实物发货接口，虚拟充值类目仅支持 API 充值履约方式，商家需要在发品阶段选择使用 API 充值履约方式，然后在生成新的虚拟充值订单后，使用平台新增的order.rechargeResult接口回传充值结果

  * 如果回传充值成功，订单自动推进到已发货
  * 如果回传充值失败或超时未回传，平台会将自动退款，取消订单



**适用类目：一级类目-虚拟充值（该类目预计于2026年1月14日左右开放）**

# 4\.  Q&A;

Q1：虚拟充值商品都必须选择 API 充值履约方式？

A1：商品发布时如果选择新增的"虚拟充值"类目，那么发货模式必须选择 API 充值履约方式，其生成的新虚拟充值订单，则必须使用开放平台新增的order.rechargeResult接口回传订单的充值结果，原有的发货方式一律禁用，但对于使用原有的充值类目(即将下线)的存量商品，其履约方式不变，仍然可以通过千帆平台或开放平台的order.orderDeliver接口进行发货履约。新虚拟充值订单可以通过order.getOrderDetail查询订单详情接口中返参中的orderTagList字段判断含有 API_RECHARGE订单标签来进行识别

  


Q2：新虚拟充值订单什么时候自动取消？

A2：根据选择的发货时间类型，自动取消的超期时间规则有所不同，如果选择即时充值，那么超期时间就是支付时间+12h，如果选择定时充值，那么超期时间就是设置的定时日期+12h

  


Q3：新虚拟充值订单的即将取消消息如何正确处理？

A3：由于新虚拟充值订单在超期后会自动取消，这里建议商家采用以下两个措施以提高订单到账时效和降低潜在资损风险，首先是商家在回传充值结果时，如果出现调用超时或系统异常的失败情况时需要自行多次重试，提高接口调用成功率，其次是商家需要接入消费新提供的msg_fulfillment_soon_cancel订单即将取消消息，在收到该消息时需要及时核对实际充值状态和平台订单状态，进行充值回传补偿调用，保证平台和商家内部充值状态一致性
